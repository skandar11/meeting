# Форма операции

Операция — одно оформленное действие: что агент делает, когда пользователь просит.
Лежат в `vault/operations/`, по файлу на действие. Агент работает **по операции,
а не по памяти** — поэтому она пишется так, чтобы её можно было выполнить,
не додумывая.

(До 2026-07-30 операции назывались «ранбуками» — в базах, собранных раньше,
папка может называться `runbooks/`; это то же самое, переименование — по слову
владельца при приёме новой версии кита.)

Операции бывают двух родов, и нужны **оба**:

- **на запись** — завести, поправить, отметить, принять, закрыть;
- **на ответ** — на каждый вопрос, который пользователь задаёт регулярно.

База только с записью перевёрнута: человек чаще спрашивает, чем диктует.

## Пример

~~~
---
тип: операция
действие: новый-клиент
вызов: фраза
исполнитель: агент
статус: live
---
# Операция — новый клиент

**Когда:** «запиши нового: <имя>, <телефон>, <что нужно>».

**Шаги:**
1. Проверь дубль — поиск по фамилии в `клиенты/`. Совпадение → уточни, не плоди.
2. Создай `клиенты/<фамилия-имя>.md` по [[vault-template]].
3. Названа услуга → свяжи с ней по [[другая-операция]].

**Крайние случаи:** услуга не названа → карточка есть, впишем позже.
~~~

## Заголовок — пять полей

- **`тип: операция`** и **`действие:`** — на языке владельца, через дефис.
- **`вызов:`** — кто дёргает: `фраза` (владелец говорит — обычный случай) ·
  `скилл` (оператор слэшем; сам скилл — тонкий указатель сюда, истины не содержит) ·
  `событие` (hook/cron — без человека).
- **`исполнитель:`** — кто делает тело: `агент` (по шагам словами) ·
  `код → <путь>` (скрипт/конвейер; код лежит рядом с vault — **в vault кода нет**).
- **`статус:`** — `possible` (замечена, не построена) · `in-dev` (строится) ·
  `live` — **только после прогона на живом случае**, не раньше.

## Обязательные части

- **`# Операция — <название>`** — как человек назвал бы это действие.
- **«Когда»** — фразы пользователя, которые запускают операцию, **его словами**.
  Не описание действия, а живые реплики: агент узнаёт операцию по ним. Формулировок
  бывает несколько — перечисли.
- **«Шаги»** — нумерованный список. Каждый шаг называет **конкретный файл**,
  который меняется, а не «обнови базу». Три особых рода шага:
  - смежное действие → ссылка `[[другая-операция]]`, не пересказ её шагов;
  - внешний инструмент → по памятке из `vault/tools/` ([[tool-template]]),
    не по памяти;
  - решает человек → пометка **`⏸ operator:`** что показать — дальше по его
    слову. Всё, что уходит наружу (публикация, отправка, заливка в чужую
    систему), проходит через такой шаг обязательно.

## По желанию

- **«Крайние случаи»** — что делать, когда сказано не всё.
- **Отдельная жирная секция на вариант действия**, который ведёт себя иначе.
- **«Не здесь»** — что похоже, но делается другой операцией, со ссылкой.
- **«Важно»** — правило, которое легко нарушить.

## Правила

- **Одна операция — одно действие.** Смежное → ссылка, а не пересказ.
- **Цепочка операций к бизнес-исходу — это процесс** ([[process-template]]):
  процесс знает свои операции, операция своих процессов не перечисляет.
- **Чего агент не знает — пиши прямо**, чтобы он не считал сам. Формула:
  «сколько именно — говорит владелец, сам не считай».
- **Шаг, меняющий деньги или счётчик, заканчивается пересчётом подытогов** —
  иначе файл разъедется с итогом.
- **В операции на ответ обязательно сказано, где база врёт:** что пустая клетка
  не ноль, что «нет отметки» не долг, что незаполненное поле не отсутствие.
- **Новая операция → две строки следом:** в чартер `CLAUDE.md` и в карту
  `vault/HOME.md`. Операция, о которой не знает чартер, для агента не существует.

Живые операции обоих родов — в разборе `../examples/leader-chess.md`
(там они ещё под старым словом «ранбук»).
