# Версия кита

Версия — **дата**. Ставится в `kit/status.md` поставки при каждой поставке и при
каждом приёме новой версии, чтобы было видно, от какого кита база отошла.

Новое сверху. Строка — только про то, что меняет форму поставки или правило;
приборка текста версии не получает.

## 2026-08-04

- **Имя файла вопросов — `questions-ВЛАДЕЛЕЦ.md`** вместо `questions-<владелец>.md`.
  Угловые скобки NTFS запрещает: на Windows `git clone` базы падает на checkout,
  а не при открытии файла. Заглушка в имени осталась заглушкой — её так же
  заменяют именем владельца при заведении базы. Вскрылось на одной из поставок
  (машина владельца — Windows).
- **Слово формы: `template/` вместо `skeleton/`** — запись задним числом.
  Переименование сделано 2026-08-02 вместе с ретайром слов «skeleton» и
  «скелет», но строки в этом файле не получило, поэтому для живых баз осталось
  невидимым: операция [[prinyat-novuyu-versiyu-kita]] сверяется по версии.
  Базы на копии 07-30 держат старое слово, пока приём не запущен.

## 2026-08-02

- **Форма поставки — один неймспейс** (слово владельца линии 2026-08-02:
  «передавать клиентам папку, где есть всё; запуск всегда с одной папки — агент
  разберётся»). Прежняя форма «две папки и два агента» снята. Поставка —
  репозиторий: дверь `CLAUDE.md` в корне, `meta-vault/` неймспейса, домены
  (`<домен>/CLAUDE.md` + `<домен>-vault/` + папки данных рядом), кит внутри,
  `engine/`, `transit/`; `secrets/` вне git. Форма выведена из двух живых баз,
  перешедших на неё 2026-08-01 и 2026-08-02, а не придумана.
- **Кит внутри поставки называется `kit/`, не `meta/`.** Имя `meta/` столкнулось
  с `meta-vault/` неймспейса — дефект вскрыт первой живой неймспейс-базой
  (2026-08-01) и там же снят переименованием. `local/` и `status.md` меты живут
  внутри `kit/`, их устройство не изменилось. Слово `meta/` заменено на `kit/`
  по всем текстам кита: шаблоны меты, операции приёма версии и прогона.
- **«Одна база — один агент — один чартер» → «один домен — одна дверь — один
  волт».** Второй чартер внутри базы — это второй домен неймспейса, не вторая
  база. Разрез доменов — по процессам владельца, не по товарам и не по темам;
  объект, который тянется через все домены, — карточка, не папка. Между
  доменами ссылаться можно, писать нельзя.
- **Дверь репозитория ([[repo-door-template]]) переписана под неймспейс:** карта
  доменов таблицей, мета-волт, «не домены», запуск всегда с корня. Дверь
  заводится каркасом ([[new-vault]], шаг 1), при передаче доводится (доступ,
  «что есть и чего нет»). Раздел SSH-доступа не менялся. Формы записи уезжают
  копией в `meta-vault/forms/` неймспейса.
- **Прогон проверки связей** ([[progon-proverki-svyazey]]): скоуп — неймспейс
  без `kit/`; кит — отдельная база Obsidian, прогоняется отдельно из своего
  корня.
- **Папка payload переименована: `skeleton/` → `template/`** (слово владельца
  линии 2026-08-02). Термин взят из словаря линии, а не придуман: жанр
  «копируемая стартовая база» здесь и так назывался template (шаблон
  неймспейса `meta-vault-template`, public template, формы `*-template`).
  По-русски — **шаблон**; слово «skeleton» из линии убрано совсем. Старая
  папка уходит штатным затиранием копии при приёме версии.
- **`template/` этой версией не перестроен** — он остался однодоменным
  (`CLAUDE.md` + `vault/`); рецепт [[new-vault]] говорит, как его файлы
  раскладываются по неймспейсу. Перестройка payload — отдельным заходом.

## 2026-07-30

- **Слово формы: «операция» вместо «ранбук»** (устав операций, слово владельца
  линии 2026-07-30). Папка процедур новой базы — `vault/operations/`; форма —
  [[operation-template]]. Шапка операции получила поля `вызов: фраза | скилл |
  событие` и `исполнитель: агент | код → путь`, статус `possible | in-dev |
  live` (live — только после прогона на живом случае); шаг, где решает человек,
  помечается `⏸ operator`. **Живые базы этой версией не переименовываются** —
  переезжают штатно через [[prinyat-novuyu-versiyu-kita]], по слову владельца
  базы; до переезда их `runbooks/` — то же самое под старым словом.
- **Две новые формы:** [[tool-template]] — памятка внешнего инструмента
  (`vault/tools/`: как пользоваться; ключи — только указателем в secrets-map;
  логин и капча — всегда человек) и [[process-template]] — процесс, цепочка
  операций к бизнес-исходу (`vault/processes/`; процесс знает свои операции,
  операция своих процессов не перечисляет). Обе папки заводятся с первым
  файлом, не заранее.
- Слово «операция» в старом смысле «запись данных» из форм убрано (чартер
  шаблона, `status.md`): записи данных — в зонах, операции — в `vault/operations/`.

## 2026-07-29

- **Доступ клиента к репозиторию стал частью формы поставки.** В двери
  ([[repo-door-template]]) появился раздел «Доступ к репозиторию» — SSH-ключ,
  который клиент генерирует **у себя**, и вставка публичной половины формой на
  GitHub. Правило выведено из живых попыток: браузерный `gh auth login` у клиентов
  падает устойчиво (истекающий код, не тот браузер, корпоративный SSO), а ключ эти
  отказы обходит. Два запрета записаны прямо: **deploy key не предлагать** (он
  per-repo, а единица поставки — организация) и **приватную половину не пересылать
  никогда** (ключ, проехавший каналом связи, равен паролю).

## 2026-07-28

- **Форма поставляемой меты дописана до конца:** `meta/` = копия кита + `local/`
  (своё, кит его не трогает) + `status.md` (мета-вход). Появились шаблоны
  [[meta-status-template]] и [[local-template]] и три ранбука меты в
  `meta-vault/runbooks/`.
- **Кит отгружаем по построению.** Внутренние накопители и имена других
  поставок из него убраны: кит уезжает клиенту целиком, значит в нём не должно
  быть ничего, чего клиенту видеть нельзя. Рабочие записки между сессиями
  конструктора живут **вне кита**, у того, кто его развивает.
- **Два правила расширены, потому что живая база им противоречила** — обе
  редакции оказались верными для своего случая, и правило разведено по области
  действия вместо выбора победителя:
  - язык служебных полей заголовка — один на базу, любой из двух, записывается
    в `principles.md` базы;
  - различение «владелец подтвердил» / «агент снял» — обязательно для баз,
    собранных из снимков чужих систем, и не нужно там, где владелец наполняет
    базу сам.
- **`local/` больше не гитигнорится — и это важно.** До этой версии кит гитигнорил
  `local/` как черновую папку, а решение о форме меты тем же именем назвало слой,
  который обязан уехать владельцу. Две вещи под одним именем, и проигрывала та,
  которую нельзя терять: журнал устройства базы молча не попадал в поставку.
  Теперь `local/` — только уезжающий слой; черновое, что в git не идёт, называется
  `scratch/`.
- Штамп версии (этот файл).
