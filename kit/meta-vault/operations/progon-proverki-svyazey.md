# Операция — прогон проверки связей и имён

**Когда:** «проверь базу», «всё ли на месте», «ничего не сломалось?», а также
**обязательно** — перед передачей базы и после любой правки раскладки.

**Зачем прогоном, а не глазами.** Битую ссылку и коллизию имён глазами не видно:
файл открывается, текст читается, а связь мёртвая. Единственная честная проверка —
прогнать и сравнить числа. Число без прогона в `status.md` не пишется.

**Шаги.** Запускать из корня неймспейса. `kit/` в скоуп не входит — это
отдельная база Obsidian, прогоняется отдельно из своего корня; поэтому в
командах он исключён.

1. **Имена файлов уникальны.** `README.md` и `CLAUDE.md` — исключение, на них по
   правилу не ссылаются скобками; всё остальное в выводе — коллизия.

   ```sh
   find . -name '*.md' -not -path '*/secrets/*' -not -path '*/.git/*' \
     -not -path './kit/*' \
     -exec basename {} \; | sort | uniq -d | grep -v -e '^README.md$' -e '^CLAUDE.md$'
   ```

2. **Битые связи.** Собрать все цели ссылок, вычесть существующие имена файлов.
   Остаток — ссылки в пустоту (либо намеренные метки «стоит завести»: тогда их
   надо знать поимённо, а не «примерно ноль»).

   ```sh
   grep -rho '\[\[[^]]*\]\]' --include='*.md' --exclude-dir=kit . \
     | sed -e 's/^\[\[//' -e 's/\]\]$//' -e 's/\\|.*$//' -e 's/|.*$//' -e 's/#.*$//' \
     | sort -u > /tmp/celi
   find . -name '*.md' -not -path '*/.git/*' -not -path './kit/*' \
     -exec basename {} .md \; | sort -u > /tmp/imena
   comm -23 /tmp/celi /tmp/imena
   ```

3. **Ссылок на папки нет.** На папку ссылка не работает никогда — файла с таким
   именем не существует. Вывод должен быть пуст.

   ```sh
   grep -rn '\[\[[^]]*/' --include='*.md' --exclude-dir=kit .
   ```

4. **Пипа в таблицах экранирована.** Без косой строка таблицы рвётся ровно в этом
   месте, и глазами это не видно. Вывод должен быть пуст.

   ```sh
   grep -rnE '^\|.*\[\[[^]]*[^\\]\|' --include='*.md' --exclude-dir=kit .
   ```

5. **Секретов в трекаемом нет.** Проверять именно `git grep` — он смотрит
   индекс, а не рабочее дерево.

   ```sh
   git grep -nEi '(api[_-]?key|token|password|passwd|secret)[[:space:]]*[:=][[:space:]]*[A-Za-z0-9_/+.-]{16,}'
   git status --short --ignored | grep secrets   # secrets/ должен быть ignored, не tracked
   ```

6. **Записать числа** в `kit/status.md`, раздел «Здоровье базы»: сколько связей
   проверено, сколько битых, дата. Ноль без даты — не запись.

**Крайние случаи:**

- **Ложные срабатывания шагов 2 и 3 — на самих правилах.** `principles.md` и формы
  показывают битые ссылки как **пример того, как делать нельзя** (`[[catalog/kody]]`,
  `[[id\|Имя]]`). Grep не знает про обратные кавычки и считает их за связи. Прежде
  чем чинить — посмотреть, не образец ли это; правило не правят под линтер.
- **Ссылка в соседний волт всегда битая, и это не опечатка.** В поставке две базы
  Obsidian: неймспейс (домены + `meta-vault/`) и `kit/`, связи через границу не
  ходят. Нашлась такая — заменить путём в коде, а не «починить» ссылку: починить
  её нельзя.
- Шаг 2 выдал имена, которых правда ещё нет, и это намеренно → они остаются, но
  перечисляются в `status.md` списком. «Битых 0» тогда писать нельзя; пишется
  «битых N, все намеренные, список там же».
- База не в git → шаг 5 делается поиском по дереву, и это надо отметить: без git
  гарантии «не уехало» нет.

**Не здесь:** правка того, что прогон нашёл. Прогон только считает. Коллизию имён
разводят переименованием файла **данных**, а не карточки зоны, — иначе поедут
ссылки.
